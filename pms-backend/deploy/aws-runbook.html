Runbook

  1. Lanzar la EC2 Ubuntu 24.04 LTS, t3.small, 20 GB gp3. Security Group: 22 (tu IP), 80, 443. Asocia una Elastic IP.
  2. Instalar Docker + Compose 
    # en la instancia, por SSH
sudo apt-get update
sudo apt-get install -y ca-certificates curl git
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker ubuntu   # reabrir sesión
  3. Subir el proyecto y configurar el entorno 
    git clone <URL_DE_TU_REPO> pms && cd pms/pms-backend
cp .env.example .env
nano .env   # JWT_SECRET, DB_PASSWORD, RABBITMQ_PASS, MAIL_*
  4. Crear el esquema y sembrar (una sola vez) 
    docker compose -f docker-compose.prod.yml up -d db redis rabbitmq
docker compose -f docker-compose.prod.yml run --rm app node dist/src/main.js --init
  5. Desactivar la sincronización del esquema y levantar todo
    Edita .env y pon DB_SYNCHRONIZE=false antes de continuar: con 2 workers, si sigue en true, ambos crean el esquema a la vez y uno falla.
    nano .env               # DB_SYNCHRONIZE=false
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps   # todo healthy
  6. Verificar 
    curl -i http://localhost/ping
curl -s -X POST http://localhost/api/users/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"superadmin@pms.local","password":"Super@2026"}'
# -> 200 + accessToken  (cambiar la contraseña)
  7. HTTPS (opcional) Con un dominio apuntando a la Elastic IP: certbot en modo webroot, copiar el certificado a deploy/certs/ y descomentar el bloque 443 de deploy/nginx/nginx.conf.

Checklist de operación

  • Backups: pg_dump periódico + Lifecycle Manager de EBS para snapshots.
  • Actualización: git pull y docker compose -f docker-compose.prod.yml up -d --build.
  • Logs: docker compose -f docker-compose.prod.yml logs -f app.
  • Secretos solo en .env (ignorado por Git), nunca en la imagen.
  • Cambiar la contraseña por defecto de superadmin.
Artefactos en el repo: pms-backend/Dockerfile, docker-compose.prod.yml, deploy/nginx/nginx.conf, .env.example y DEPLOY-AWS.md.
